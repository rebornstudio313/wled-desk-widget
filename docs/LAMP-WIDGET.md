# Лампа для виджета WLED Desk

Готовая Canvas 2D лампа с прозрачным фоном, формой по согласованному референсу,
цветным свечением и вдавленной подсвеченной надписью WLED DESK.

## Структура

```text
runtime/                  Готовый модуль и необходимые материалы
  lamp-canvas.mjs         Экспорт CanvasLamp
  lamp-ribbon.mjs         Рисование, форма, свечение и надпись
  lamp-material.mjs       Загрузка материалов и карты цветов вдоль ленты
  lamp-widget-host.mjs    Адаптер кадров для виджета (до 20 кадров/с)
  *.png                   Материалы основания и ленты, две UV-карты
  lamp-calibration.json   Размеры и эталонная палитра
integration/
  LampWidget.tsx          React-компонент для существующего watchPeek
  lamp-mode.css           Прозрачный режим лампы
  install.mjs             Установка/обновление в проект WLED Desk
  lamp-widget-smoke.mjs   Проверка кадров Peek на локальных тестовых лампах
design/                   Исходный референс и пример надписи
index.html                Демонстрация, не управляет устройствами
preview.mjs               Локальный HTTP-сервер демонстрации
Открыть лампу.cmd          Запуск демонстрации (нужен Node.js)
```

## Уже подключено к нашему виджету

Проект: `../Widget LED RGB`.

ПКМ по виджету → **Режим «Лампа»**. В том же меню выберите источник под
надписью **Лента для лампы**. Выбор сохраняется отдельно от группы управления.
ПКМ → **Обычное управление** или кнопка под лампой возвращает панель.
Режим сохраняется после перезапуска.

Отрисовка получает кадры из существующего `watchPeek`: в браузере используется
тот же SSE backend, в Tauri — существующий native Channel. Второй транспорт не нужен.
Одновременно работает только одно представление Peek — края панели либо лампа.
В режиме лампы Peek работает независимо от настройки подсветки краёв.
Если устройство выключено, источник сменился, кадры перестали приходить или окно
скрыто, старая картинка гасится. Без устройства нет выдуманной анимации.

Лампа — просмотр, выбор источника не меняет свет устройства. Peek уже содержит
яркость контроллера, поэтому повторно умножать кадр на `state.bri` не нужно.
Геометрия, тени и надпись постоянны, цвета идут от первого крепления ко второму.
Рендер ограничен 20 кадрами/с и хранит только последний ожидающий кадр.

## Повторная установка / обновление

Из этой папки:

```powershell
node integration/install.mjs "C:\Users\rebor\Desktop\Widget LED RGB"
```

Скрипт проверяет проект, создаёт резервные копии затрагиваемых файлов в
`.local/lamp-widget-backups/`, копирует runtime в `apps/desktop/public/lamp-widget/`,
а компонент и стили — в `apps/desktop/src/`. Повторный запуск обновляет модуль.
Затем в проекте выполните `node scripts/build-frontend.mjs`; для настольного exe
нужна обычная native-сборка проекта. Папка лампы не нужна установленному exe:
все ресурсы включаются в сборку. Исходную папку стоит хранить для обновлений.

Проверка интеграции в проекте: `node tests/integration/lamp-widget-smoke.mjs`
или `pnpm test:lamp`. Она использует локальные тестовые WLED и отдельный временный
профиль, не меняя реальные ленты.

## Подключение к другому Canvas-хосту

Разместите весь `runtime/` на одном HTTP origin, сохраняя имена файлов:

```js
import {createLampWidget} from './runtime/lamp-widget-host.mjs';
const lamp = createLampWidget(document.querySelector('canvas'), {maxFps:20});
// На каждый декодированный Peek-кадр:
lamp.update({colors:frame.colors, on:true});
// При выключении, потере связи, смене источника:
lamp.clear();
// При удалении компонента:
lamp.destroy();
```

`colors` — массив `#RRGGBB` или RGB-троек 0–255, от 1 до 16384 значений.
Невалидный кадр возвращает `false`. Размер canvas задаётся CSS, рекомендуемое
отношение сторон 2:3. Фон прозрачный, масштабирование учитывает DPR.
Ресурсы загружаются через fetch и Image: открывайте через HTTP, не через file://.
При CSP разрешите скрипты, изображения и connect-src своего origin.

Материалы растровые 640×960; для значительно большего размера потребуется
перекалибровка исходных материалов. Для мини-виджета разрешения достаточно.
